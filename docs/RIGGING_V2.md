# Rigging v2: Tripo donor, original character

## Facial expressions

After body transfer, fixed supports, fitted hair/clothing chains and weight refinement, use **Rigging > Facial expressions**. The user confirms the body deformation review before preparing this handoff. This is a separate stage of shape keys, not new facial bones. The maintained profile is `shared/facial-profile.js`; instructions are generated by `server/avatar-delivery.js`. The ZIP contains only instructions and paths, never models or skills. The local manifest binds the current placement, donor, body revision and latest manual weight edit rooted in that original; donor-only edits are never a final source.

Open the connected editable body copy, preserve `_workbench_vertex`, neutral geometry, UVs, textures, custom hair normals, existing morphs, skeleton and weights. If the authoritative original GLB contains newer manual weights, reconcile them on the connected BLEND before authoring. Do not split the editable face at UV seams or reimport a raw split GLB as the editable source. Work in background Blender, on copies. Do not add topology, extra jaw/eye bones, ImageGen textures or a realistic jaw-flap rig.

Create bilateral and individual blinks; left/right/up/down gaze; raised, lowered, angry and sad brows; smile/frown; and the 15 speech visemes. Fit lip contours to the actual mouth and anime proportions: opening, narrowing and widening should mainly deform lips and their immediate support. Keep the mandibular silhouette stable with only a small fitted chin motion. Inspect the oral cavity; disclose a missing interior rather than tearing a sealed mouth or inventing visible teeth. Neutral silence may be represented by empty bindings in FITA; check the actual Unity import strategy later.

Apply [the maintained facial expression guide](FACIAL_EXPRESSIONS_WORKFLOW.md), copied into every facial handoff. **A blink must never shrink, flatten, scale or deform iris, pupil or glints.** Close the lids/lashes; keep the iris assembly still or, only to clear actual protrusion, translate all its layers together a minimal distance inward. The importer limits this retreat to the lesser of 1 mm and 5% of iris diameter. Inventory every ocular piece with exact mesh name, role and anatomical eye in `report.coordinatedParts`, including fixed parts. Protect nose and cheek silhouette. For gaze keep the approved coordinated iris/pupil/glint approach; do not confuse lid compression with ocular deformation. Explicit per-expression bindings synchronize separate renderers; equal key names alone do not.

Use readable moderate angry brows; sad brows accompanied by a slight lower-lid lift; smiles/frowns driven from the actual lip corners with smooth local falloff and a stable centre; visible lip contact/pressure for P/B/M; and a more legible I viseme. Preserve the raised-brow skin follow and the other fitted speech/gaze poses. These are visual acceptance criteria, not claims that numeric morph differences prove a convincing expression.

Preserve the same fitted face-mask normal field across skin, lids, lashes, brows, sclera, iris, pupil and glints. Include the chin and its underside with smooth jaw transitions. Every new facial POSITION morph must include baked NORMAL deltas sampled from this smooth field in its deformed pose; collapsed eyelid triangle rotations must not drive shading. Review neutral, intermediate poses and combinations with front/side/back MToon lighting. Preserve base custom normals and NORMAL morph targets through destination export. Base-normal changes on an existing rig require the explicit source-bound procedure in the facial guide.

Review each pose at 0/.25/.5/.75/1 from front, three-quarter and both sides; also test blink+gaze, smile+visemes and brow+mouth. Check intersections, mouth seams, chin stability and continuous source-vertex deformation across UV seams. Keep joints at neutral and all shape values at zero for export. Distinct visemes must actually be distinct; aesthetic success must not be inferred from a target count.

The local handoff specifies `output/candidate.glb`, `facial.blend`, `bindings.json`, `report.json`, unchanged `manifest.json` and review evidence. The importer validates neutral surface/UV/base-color preservation, connected source identities and consistent seam deltas. It appends the new morph data to the approved original GLB, keeping its original binary data, skin, weights, materials and existing morphs. The candidate's body data never replaces the original. The BLEND validation checks connected topology; it does not prove matching weights or artistic quality. Reconcile and verify the editable file against the authoritative GLB again before any Unity export. Import produces a **needs-review** revision; the user tests the coordinated sliders and approves that exact revision. Source changes or new facial results invalidate that approval.

After approval use **Export > Export for VRChat**. This prepares the next instructions-only ZIP referencing `docs/VRCHAT_PC_CODEX_HANDOFF.md`. Do not perform Unity setup during body refinement or silently publish from facial approval. Reopening Rigging from Export removes the active export handoff and preserves the body/facial work for editing; reopening an earlier stage invalidates downstream rig/facial/export records while retaining archived data.

Implemented on 2026-10-13. This replaces fitting the v1 template from scratch in the primary Rigging interface. Previous v1 runs remain in the history.

## Source ownership and handoff

The finished Placement GLB contains the complete approved character. The original GLB and editable Blender scene remain the authoritative geometry, UVs, materials and textures. Tripo supplies a donor skeleton, its joint placement and hierarchy, and starting skin weights. Its meshes are reference data and must never become the final character.

The two steps in Rigging are:

1. **Send character to Tripo** uses the paired extension to upload the current complete character, open its observed Rigging link and select Unity Humanoid compatible. Preparation stops at the observed price. A separate user click confirms that exact quote before submission. Monitoring then downloads a GLB with its skeleton and imports it as a donor. **Import an existing Tripo result** is also available.
2. **Download refinement ZIP** provides instructions, exact local paths to the manifest, models, instructions and `AUXILIARY_PROFILE.json`; the ZIP contains only instructions and paths. Codex transfers the donor rig and weights to copies of the original meshes, applies the fixed support-bone profile and performs focused weight cleanup. **Load refined result** validates and snapshots the returned files for review.

## Fixed support profile and deferred shape keys

The existing `templates/rigs/auxiliary-v1.json` now specifies `humanoid-support-v2`. The filename remains stable. All humanoids use 26 fixed roles (13 per side): three upper-arm, three forearm and three thigh twist zones at 25/50/75 percent rotation, elbow/knee volume branches, and breast/glute tissue anchors. Fit anatomy and local frames per character; do not omit roles or duplicate verified donor equivalents. Swing-following twist branches pivot at the anatomical joint. Tissue anchors are weighted branches prepared for later physics, not a simulation.

The required order is donor skeleton/starting weights transferred to the connected original -> all fixed body support bones -> character-specific hair/clothing chains -> regional weight refinement -> pose review. Preserve donor joints and parents, original topology, UVs, textures, normals and existing morphs. Facial rig/expressions/visemes have their own later section. New body corrective shape keys remain deferred.

`runtime.supportBones` maps canonical roles to actual names, while `twists` and `correctives` describe reproducible motion. `runtime.secondary` declares ordered chains, attachment, mesh names, region, kind and `simulated:false`. These chains follow their parents in the viewer; destination physics is configured separately. Hair chains follow the hairstyle's independent masses and protected roots. Loose clothing chains follow actual panels and attachments; fitted fabric follows the body. A mesh inventory must justify all decisions rather than silently skip hair or clothing.

Use `refine_regions` from the existing `server/blender/rig_weight_exchange.py` after fitting bones and painting initial helper masks. It accepts explicit disjoint regions of connected source vertex indices, allowed bones, fallback support and smoothing locks. It removes forbidden influences, smooths only edge-connected neighbors in the same region, then prunes and normalizes to four influences. It does not infer anatomy, generate missing helper masks or certify visual quality. Local smoothing is appropriate at shoulders/axilla, hips/groin, elbows, knees, ankles and chain attachments; avoid global smoothing over rigid accessories, fingers, separate layers or nearby opposite limbs. Preserve source identity and identical weights on exported UV duplicates.

New refinement runs pin the required support profile. Downloading a fresh handoff upgrades the guidance/profile for an older run without altering source assets or accepted snapshots. Import requires all fixed roles to be weighted with matching recipes/attachments, valid secondary chains and no undeclared added bone families. It also requires the complete mesh inventory, an exported-weight-consistent audit and pose evidence for both sides. Protected regions must show no unintended motion above 1 mm; define those regions explicitly and exclude intentional torso/pelvis transitions. PNG/JPEG evidence is required under `output/review/`. Passing structure and evidence-presence checks is not artistic certification; results remain `needs-review`.

Downloading a ZIP refreshes the handoff instructions and profile beside its manifest without changing protected inputs or existing results. Legacy ZIPs already copied elsewhere should be downloaded again to receive this scope.

## Manual weight editing in Blender or Maya

The Rigging panel now exposes **Download GLB**, **Download FBX** and **Upload edited weights** for the selected refined rig, donor, or accepted manual revision. Donor edits remain explicitly donor-based references; they do not silently replace the approved original character. FBX is binary and generated using locally installed Blender, in a background process with scripts disabled. This flow does not require Tripo or a paid operation.

An immutable local exchange session binds the upload to the downloaded source. Uploads must retain the rest geometry, triangle corners/winding, UVs, original mesh names, existing bones and their rest transforms/parents, materials/images and existing shape keys. Adding branch bones is supported. Weights must be normalized and contain at most four influences per vertex. Original sources and previous accepted revisions are retained.

Blender is used to inspect GLB/FBX files. The implementation does **not** replace the original mesh with the uploaded mesh: it patches only skin-weight accessors and new bone/bind data onto the original GLB. Every original geometry, normal, UV, image and morph buffer stays byte-identical. Format-induced vertex reordering or merging of identical encoded seam vertices is accepted only when the rest triangle/corner correspondence remains equivalent within 0.00001 meters; the final vertex count and connectivity remain those of the downloaded source. Ambiguous weight correspondence is rejected. Conversion cannot prove artistic deformation quality.

Existing viewer recipes remain attached to the manual revision. New bones inherit parent motion; independent twist/corrective behavior requires corresponding runtime configuration and is not inferred from FBX constraints. This upload step does not import arbitrary Blender drivers or Maya expressions. Source normals and other unsupported shader metadata are retained from the original even if a format does not carry them equivalently.

Acceptance checks performed on Example: both Blender GLB re-export and binary FBX round trips were accepted with 18 meshes, 43,885 exported vertices and 73 bones. Original binary geometry/material data remained an identical prefix of the output. Separate synthetic Blender cases validated changed weights and an added weighted bone, and rejected moved geometry, removed bones, UV edits, new shape keys and material changes. Maya itself has not been exercised; use its binary FBX export in rest pose, with no animation or automatic leaf bones.

Run `node --test tests/rig-manual.test.js` for the HTTP/session gates. Run Blender with `--background --factory-startup --disable-autoexec --python-exit-code 1 --python tests/rig_manual_blender.py -- <temporary-test-folder>` for real conversion/negative tests.

The small ZIP deliberately does not embed the large model files. It is not a portable handoff to a remote computer without the workspace.

```text
projects/<project-id>/rigging/<run-id>/
  manifest.json
  INSTRUCTIONS.txt
  input/
    original.glb
    original.blend
    donor.glb
    donor-profile.json
    runtime-example.json
    reference_*.png
  output/
    rigged.glb
    rigged.blend
    manifest.json
    runtime.json
    report.json
  reports/
```

Input checksums and source identities bind each run to its placement and donor. Changing placement or donor requires a new run. Repeated preparation of the same source pair returns the existing run. Returned versions are stored separately from the original inputs.

## Transfer and validation

Do not assume vertex indices match between the original and Tripo export. Align the donor globally by a uniform scale, rotation and translation, then transfer weights between matching parts using verified correspondence or nearest-surface barycentric interpolation. Preserve all anatomical joint names, direct parents and aligned world joint positions. Additional deforming helpers belong in branches rather than inside Humanoid chains.

The donor parser accepts structurally valid imperfect initial weights; it reports normalization and unweighted vertices without calling them good deformation. The returned model must have finite, nonnegative normalized weights, at most four influences per vertex, valid joint indices, inverse bind matrices and skinned meshes. The importer also checks:

- The manifest, input hashes and current source identity.
- Original rest triangles, UVs and base-color material/image signatures within the defined tolerance. This is not a complete equivalence test for every possible material extension.
- Required donor bones and hierarchy, plus world joint positions under the reported global similarity transform.
- A bounded declarative runtime for added auxiliary bones and corrective morph targets.
- An editable Blender file header and the required review report. The connected-source path also runs the editable Blender connectivity guard. Audit/evidence presence does not independently prove artistic quality.

Data passing these checks is marked **needs-review**. The web viewer and representative Blender poses must still be reviewed for leakage, collapsing volume, shoulder behavior, clothing and separate facial parts.

## Preview behavior

### Editable connectivity and UV seams

The 2026-10-13 Example audit traced the disconnected sweater to a GLB round trip,
not the semantic segmentation itself. The reconstruction .blend has one sweater
component (4,468 vertices / 8,904 faces); its textured GLB has 5,394 encoded
vertices / 38 index-connected islands. Placement imported those seam copies
without restoring editable connectivity. Surface/UV-only validation did not
detect this difference.

`mesh_connectivity.py` now exports `_WORKBENCH_VERTEX` source identities and
restores only authorized copies in our importer. UVs and normals remain corner
data. Conflicting positions, skin weights or shape keys cannot be averaged by
this restoration. Legacy manual placement uses the saved reconstruction and
triangle/corner correspondence when available; generic legacy imports use
Blender's attribute-aware merge option, which cannot recover all original
topology without provenance. Do not use a global Merge by Distance.

Placement exposes immutable connected Blender/FBX downloads through
`placement/:placementId/editable/:format`. For historical placements, source
corner metadata restores connectivity while retaining approved neck/hair edits.
The original GLB and historical .blend remain untouched. GLB must still encode
UV seams with multiple vertices; use the editable formats in external editors
or our identity-aware importer. The GLB format itself cannot share one vertex
across different UV values.

Example's repaired download and the newly generated neck package both reopen with
the sweater as one connected component. UVs, face positions/material assignments
are checked before and after repair. Four ambiguous coincident shoe faces and
one hair source vertex with differing edited positions are deliberately retained
without guessing; the derivative's report records these exceptions. Existing
rig refinements are not overwritten. New weight-edit sessions restore compatible
seam copies for FBX; uploads still patch only validated weights/bones into the
original GLB. Both a real Example FBX round trip and the eight adversarial synthetic
weight-edit checks passed after this change.

Run `tests/blender/mesh_connectivity_regression.py` inside background Blender to
check UV seams, coincident independent surfaces, round-trip identity and conflict
rejection. `tests/placement-editable.test.js` covers immutable cached downloads.

New-project rigging now validates connectivity beyond editable downloads.
The connected Placement `.blend` is the authoritative refinement input; its
POINT vertex identities must survive neck finishing, face UV rebaking and rig
export. Refinement imports validate the editable `.blend` against the source
vertex/polygon identities and validate GLB triangle-corner ownership. All GLB
copies of a source vertex must have equal named-bone weights and position morph
deltas, including copies in different material primitives. Manual weight uploads
receive the same GLB check. UV seams may still require separate encoded GLB
vertices; these checks prevent those copies from deforming independently.

Legacy sources without identities explicitly report `connectivityChecked:false`;
they are not silently certified or rewritten. A new Placement report declaring
preserved identities cannot fall back to that legacy path if GLB identities go
missing. This does not authorize welding distinct garment/hair/body pieces.

`tests/blender/rig_connectivity_pipeline.py` exercises a fresh synthetic garment
through Placement import, weighted rig export and the actual FBX weight-edit
round trip. A deliberately split editable result is rejected. The Node tests in
`tests/rig-connectivity.test.js` reject changed identities, corner ownership,
inconsistent seam weights and morph deltas; `tests/face-uv.test.js` verifies that
UV rebuilding propagates source identities. These checks establish structural
preservation, not artistic shoulder quality or a paid Tripo end-to-end test.

The app owns its test animations. Delivered GLBs do not need animation clips. Semantic aliases map the existing source names to Humanoid roles without renaming bones. Idle, arm raise, elbow bend, knee bend and wrist twist are available where the relevant joints exist. Finger curl is available when the rig includes reviewed local curl-axis metadata.

Blender constraints and drivers do not execute in a GLB. `runtime.json` uses `workbench-rig-runtime/v1` with a Humanoid name mapping, `twists` and `correctives`. The viewer evaluates bounded pose recipes rather than arbitrary code:

- Twist recipes identify a source, a new target, a target rest-local axis and a fraction; optionally preserve swing.
- Correctives measure the source's rest-local signed rotation on an axis, use a smooth ramp between two angles, and affect a helper's local transform or a named morph target.
- Axes and thresholds must be fitted and compared against Blender poses. The example file is illustrative, not a fitted recipe. Every added bone needs a supported recipe or an explicit secondary-chain declaration; approved corrective morphs retain their runtime behavior.

Simulation of the prepared hair/clothing/tissue bones, retargeted motion libraries, Unity/VRChat constraint conversion, facial visemes and tracker validation remain separate work. A Unity-oriented skeleton alone does not establish VRChat readiness.

FBX weight-edit export disables Blender's generated armature display shapes on
GLB import when the installed importer supports `disable_bone_shape`. Otherwise
Blender creates a hidden `Icosphere` used only to draw bones, which the FBX
exporter can mistakenly include as character geometry. No character mesh is
filtered by its name. New manual sessions use `fbxExportVersion:2` so they do not
reuse an older export containing that helper; historical session references are
retained for the correspondence checks on already downloaded files. The real
Blender weight-exchange regression checks that generated helper geometry is
absent while the neutral FBX round trip still passes.

## Extension connection and recovery

Extension files are version **0.2.25**, worker revision **0.2.25-rigging**. Reload the extension after updating its unpacked files. The popup offers **Reload extension** if it detects an older running worker. Restarting the local server deliberately revokes the pairing token; reconnect with a fresh project code if required.

A readable, paired Studio page is a connection, even if a particular workflow is unsupported. English and Spanish Rigging routes are recognized separately from generation controls. Connecting to Rigging must not produce the old generation-workspace-only error. Layout diagnostics remain usable on readable, authorized pages even during a popup/worker revision mismatch. Read-only observation does not close dialogs or click controls.

Submission requires an exact, unexpired quote. The extension records a submission receipt before the paid click. Uncertain replies never trigger automatic resubmission. After a lost connection, **Check existing rig job** only monitors or downloads the existing task. If its completion cannot be established, use an existing downloaded GLB rather than paying again automatically.

Large uploads use bounded chunks in the authorized tab. Rig exports use the browser's managed download path; importing checks the exact FITA download folder and the resulting GLB.
